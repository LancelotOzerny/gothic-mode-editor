# Gothic Editor 0.2 (Python / Tkinter)

Требуется **Python 3.10+**. Сторонние пакеты не требуются.

## Запуск

```bash
python main.py
```

## Порядок работы

1. «Файл → Создать проект»: выберите **отдельную** папку мода, например `D:/projects/MonasteryExpansion`. В ней появятся `project.json` и `Scripts/Content/Items/`.
2. (Необязательно) «Проект → Настройки → Ресурсы → Путь к файлам Gothic 2»: выберите корень установленной Gothic II, содержащий `_work/data/Scripts/Content`, **либо** корень распакованных исходных `.d`-файлов. Если скриптов нет, установите Gothic 2 MDK / распакуйте исходники.
3. Категории слева раскрываются нажатием, кнопка `+` создаёт новый предмет в проекте. Для проектных предметов доступны «Дублировать» и «Удалить»; для игровых — «Дублировать в проект». Двойной щелчок изменяет `name` (название в игре).
4. Справа можно редактировать выражения Daedalus; кнопка «Сохранить в проект» записывает изменения **только в папку проекта**.
5. Для 3D-просмотра `.3DS` положите распакованные модели в `Assets/Models`. ЛКМ вращает, колёсико масштабирует. Архивы `.vdf` и форматы `.MRM` пока не поддерживаются.

## Ограничения прототипа

- Редактор работает с непосредственными `INSTANCE (...) (C_Item)` и прямыми присваиваниями. Если предмет получает параметры через прототип, функции, условную логику или константы, вычисления не выполняются. Категории в таких случаях могут быть неточными; нераспознанные предметы — в «Разное».
- У скриптов Gothic нередко кодировка Windows-1251. Редактор сохраняет кодировку при изменениях существующих файлов и использует Windows-1251 для новых предметов; неподдерживаемые символы вызывают ошибку сохранения вместо порчи файла.
- Редактор **не компилирует мод**, не меняет `Gothic.src`, не устанавливает мод в игру и не разрешает конфликты определений между оригиналом и проектом. При сборке потребуется корректно заменить оригинальные скрипты проектными, а не подключать оба файла с одинаковыми `INSTANCE`.
- Удаление из проектной копии оригинального многопредметного файла удаляет его определение **только из проектной копии**, но это не эквивалентно удалению из игры до правильной сборки мода. Не импортируйте все проектные `.d` рядом с оригинальными без учёта дублей.
- Изменение поля на существующем игровом предмете копирует **весь содержащий его исходный `.d`-файл** в проект при сохранении (Copy-on-Write). Оригинал остаётся нетронутым.
- Пустые или невалидные выражения Daedalus могут не скомпилироваться. Значения вводятся как код (например, `"Зелье"`, `100`, `ITEM_KAT_POTIONS`).
- Подробная классификация некоторых разновидностей украшений, свитков и оружия эвристическая; на разных модификациях она может отличаться.
