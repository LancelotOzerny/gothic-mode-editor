# Gothic Editor 0.3 — JSON-компоненты зелий

Запуск: `python main.py` (Python 3.10+, Tkinter, дополнительные пакеты не требуются).

Это обновление существующего редактора. Остальные типы предметов продолжают работать по старой схеме.

## Как пользоваться

При запуске открывается стартовый экран с десятью последними проектами. Проект
можно открыть двойным щелчком или кнопкой «Открыть выбранный проект». В меню
**Файл → Недавнее** доступны пять последних проектов. Успешное открытие или создание
поднимает проект наверх списка; история сохраняется между запусками в
`%APPDATA%/GothicEditor/recent_projects.json`, отдельно от настроек.

Кнопка «Создать проект» на стартовом экране предлагает имя новой папки и создаёт
её рядом с последним проектом. Если история пуста или его родительская папка
недоступна, открывается выбор папки. Существующая папка при создании соседнего
проекта не перезаписывается.

1. **Файл → Открыть проект** и **Проект → Настройки → Ресурсы** (подключить папку исходников Gothic 2).
2. Выбрать зелье в секции оригинальных предметов, нажать правой кнопкой → **Дублировать в проект**. Оно появится в `Items/<INSTANCE>/`.
3. Изменить поля в панели справа, нажать **Сохранить в проект**. Теперь сохраняется `item.json`, а не исходный `.d`.
4. Для нового зелья нажать `+` у категории **Зелья**. Для дубликата — **Дублировать**.
5. **Сборка** готовит отдельную копию исходных Daedalus-скриптов в временной папке, заменяет уже существующие определения зелий и добавляет новые в `Items/GE_ComponentPotions.d`. Компилятор создаёт `build/Gothic.dat`.

## Файлы зелья

При сборке основой служат оригинальные Daedalus-скрипты из выбранной Gothic II.
Проектные `.d` накладываются по определениям, а не заменяют одноимённый файл целиком:
сопоставление идентификаторов и путей не учитывает регистр. Неполные старые копии
сохраняют остальные исходные `INSTANCE`, функции, константы, переменные и комментарии.
JSON-компоненты применяются после этого объединения. Новые определения добавляются
с проверкой конфликтов; неоднозначные совпадения останавливают сборку с указанием
идентификатора и файлов. Границы определений определяет лексический разбор строк,
комментариев и вложенных скобок; кодировка исходного файла сохраняется.
Все изменения при сборке выполняются только в рабочем дереве внутри `build/`.

Перед запуском компилятора в рабочей копии заменяется символ form feed (`U+000C`),
если он использован как пробел вне строк и комментариев. Это устраняет ошибку
`extraneous input` в некоторых исходниках Gothic, например в диалоге Ватраса.
Исходники установленной игры при этом не меняются; каждая замена отмечается в терминале.

Для совместимости с DaedalusCompiler 0.9.2 перед компиляцией переносы строк во временных
`.d` и `.src` приводятся к CRLF без перекодирования CP1251. Это предотвращает падение
диагностики компилятора на исходниках с LF или смешанными переносами строк.
При ошибке каталог `build/compile-*` сохраняется вместе с исходниками, `stdout.log`,
`stderr.log` и `diagnostics.json` (команда, рабочая директория, код завершения и параметры
окружения .NET). Общий вывод доступен в `build/compile.log`. При успешной сборке исходники
удаляются, а три файла диагностики сохраняются непосредственно в `build`.
Процесс компилятора всегда получает `DOTNET_ROLL_FORWARD=Major`.

Записи `\r\n`, `\n`, `\t` и `\"` внутри JSON-строк шаблона и функций — стандартное
экранирование переносов строк, отступов и кавычек. При чтении JSON они декодируются
в обычный Daedalus-код; удалять эти последовательности вручную не нужно.

```
Items/ItPo_Example/
  item.json        # INSTANCE, исходный текст определения и значения полей
  params.json      # переменные и ссылки на оригинальные константы
  functions.json   # ссылки на функции из оригинального файла
  functions.d      # дополнительные, ещё не объявленные функции этого зелья
```

- Исходные `INSTANCE` хранятся как шаблоны в JSON; изменяемые поля выделены отдельно.
- В `params.json` поле `variables` позволяет объявлять **новые глобальные переменные** (тип `int` / `float` / `string`, `code`). Если нужно назначить начальное значение, делайте это в функции — `default` сам по себе не выполняется в игре.
- `source_constants` содержит найденные оригинальные константы. **`override: false`** означает, что они только для справки. Установите `override: true` и измените `expression`, чтобы заменить конкретную исходную константу **во время сборки**.
- `functions.json` содержит обнаруженные обработчики `on_state` в виде исходного Daedalus-кода. По умолчанию `override: false`: функции уже есть в оригинальном скрипте. Для замены измените `source` и включите `override: true`.
- В `functions.d` добавляйте **только новые функции**. Не копируйте туда оригинальные функции, иначе возникнет дублирование символов.
- Если тот же обработчик или константа используется несколькими предметами, его изменение повлияет на них тоже.

## Нижние вкладки и ресурсы предмета

В **Вид → Окна** независимо включаются **Терминал** и **Ресурсы**. Если включены обе
панели, внизу показываются две вкладки: терминал первым, ресурсы вторыми. Если всё
выключено, нижняя область скрывается. Высота общая для вкладок, по умолчанию 200 px;
она меняется разделителем и через настройки интерфейса. При сборке терминал
включается и выбирается автоматически, сохраняя вкладку ресурсов.

В ресурсах отображаются файлы `Items/<INSTANCE>/` выбранного предмета, включая
вложенные папки. Для `ItPo_Health_01` это `item.json`, `params.json`, `functions.json`
и `functions.d`. При выборе другого предмета список меняется; кнопка **Обновить**
перечитывает содержимое папки.

В **Проект → Настройки → Ресурсы → Настройки → Путь к редактору** выберите программу,
например Sublime Text или Visual Studio. Путь сохраняется в `project.json` как
`resource_editor_path`. Двойной щелчок и пункт ПКМ **Открыть** запускают выбранный
внешний редактор с файлом. **Открыть в папке** открывает содержащую файл папку.
После редактирования JSON во внешней программе используйте **Файл → Обновить данные**,
чтобы перечитать свойства предметов в редакторе.

Другую вкладку можно добавить через
`app.register_bottom_tab(code, title_key, factory)`, где `factory(parent)` создаёт
панель внутри переданного родителя, а `title_key` — ключ в `assets/lang/<язык>.json`.
Пункт в меню **Вид → Окна** добавляется автоматически. Вкладки включаются методами
`show_bottom_tab(code)` и `hide_bottom_tab(code)`. Скрытие панели сохраняет её содержимое.

## Важные ограничения

- `item.json` для зелий поддерживается; другой тип предмета пока сохраняется старым механизмом.
- При сборке исходники игры читаются, а **созданные файлы находятся в папке сборки проекта**. Кнопка **Синхронизация** в текущем редакторе по-прежнему намеренно записывает результат в игровую папку, предварительно делая резервные копии; не нажимайте её, если хотите оставить установленную игру нетронутой.
- Сканер Daedalus — упрощённый. Для необычных макросов/вложенной логики проверяйте сформированный файл и журнал компиляции. Не заменяйте оригинал содержимым JSON вручную.
- При сборке изменения в `functions.json` и `params.json` выполняются только после явного `override: true`.
- Новые эффекты и обработчики необходимо написать на Daedalus и подключить самостоятельно; JSON пока не создаёт игровую логику автоматически.
- Старые `.d`-копии зелий автоматически не мигрируют в компонентный формат. Для них есть смысл сделать резервную копию и перенести через **Дублировать в проект** из оригиналов.
