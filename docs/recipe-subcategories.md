# Подкатегории алхимии

Категории рецептов (`Assets/Recipes/categories.json`) могут иметь необязательное
поле `parent` — идентификатор родительской категории. У существующих проектов
поля нет, и это означает категорию верхнего уровня.

Пример:

```json
{
  "schema_version": 1,
  "categories": [
    {"id": "special", "name": "Особые зелья", "binding": "special"},
    {"id": "experience", "name": "Зелья опыта", "parent": "special"},
    {"id": "exp_advanced", "name": "Усиленные зелья опыта", "parent": "experience"}
  ]
}
```

В редакторе: контекстное меню категории → «Создать подкатегорию» или выбор
поля «Родительская категория» при добавлении/редактировании.

Рецепт выбирает **конечную** категорию в своём поле категории, например
`experience` или `exp_advanced`. Для удобства в списке отображается весь
путь: «Особые зелья / Зелья опыта».

В игре:
- «Особые зелья» — штатное меню Gothic.
- «Зелья опыта» — отдельный пункт в нём, если известен хотя бы один рецепт
  внутри данной категории или её дочерних категорий.
- Внутри «Зелья опыта» показываются известные рецепты, дочерние разделы и
  кнопка «Назад».
- «Назад» возвращает к родительскому меню; «Конец» остаётся штатным игровым пунктом.
- Поддерживается несколько уровней вложенности через существующий `Info_AddChoice`,
  без дополнительных расширений движка.

При удалении категории её рецепты и дочерние категории переходят к родителю.
При переименовании ID связи автоматически обновляются. Запрещены циклы,
несуществующие родители и вложенные штатные категории Gothic.

**Проверка:** нужно собрать скрипты в пользовательском установленном Gothic 2
и проверить переходы за алхимическим столом. Тесты генератора покрывают
структуру создаваемого Daedalus, но не взаимодействие с реальным движком.
