# Порядок работы

## Выполнение

1. Найди относящиеся к задаче модули по карте архитектуры и изучи реализацию.
   При неоднозначности выбирай минимальное согласующееся с кодом решение;
   спрашивай только о том, без чего нельзя корректно продолжить.
2. Небольшую задачу выполняй сразу. Для крупной достаточно плана из 3–7 пунктов;
   отдельные заметки нужны только для сохранения действительно сложного контекста.
3. Внеси изменения и проверь затронутые сценарии. Для кода проверь синтаксис,
   для документации — корректность ссылок и примеров. Запускай подходящие тесты,
   расширяй проверку только при выявленной связи с другими компонентами.
4. Кратко сообщи результат, проверку и реальные ограничения. Предложи пользователю
   проверить изменения в исходниках или запуском из Python; старый EXE их не содержит.

## Одно подтверждение на завершение

- После проверки пользователем запроси одно подтверждение: «Всё хорошо, завершай»
  либо «Нужны правки». В том же сообщении укажи, что завершение включает сборку
  и коммит, а для пересборки EXE необходимо сохранить работу и закрыть редактор.
- Однозначное согласие пользователя уже считается подтверждением; не требуй
  точной фразы и не спрашивай отдельно разрешение на сборку, коммит или закрытие.
  Если завершение уже явно разрешено, повторное подтверждение не нужно.
- После подтверждения выполни необходимую сборку, проверь её успех и создай коммит
  только по текущей задаче с кратким сообщением на русском языке.
  При ошибке исправь причину в рамках задачи и повтори затронутую проверку/сборку.
  Не объявляй завершение успешным при оставшейся ошибке.
- Выбирай сборку по изменениям: код/ресурсы редактора — `compile.ps1`;
  контент мода — `ProjectTools.compile()`. Для одной документации сборка не нужна.
  Установка мода в игру и запуск выполняются только по отдельной пользовательской задаче.
- После подтверждения выполнения задачи из codex/ROADMAP.md обнови её статус [ВЫПОЛНЕНО] в двух местах:
- - В разделе ### Содержание — добавь отметку после номера задачи, если её ещё нет.
- - В заголовке самой задачи — добавь отметку после номера, например: ### [1.0] [номер хеша] [ВЫПОЛНЕНО] Правки иерархии в редакторе.
- - Не изменяй номера задач, названия, описания и статусы других задач.
- - Сохраняй параллельные изменения пользователя в ROADMAP.md.
- - После создания коммита сообщи его хеш.

## Экономия контекста

- Ищи через `rg`, затем читай нужные функции/разделы. Не выводи целые большие файлы
  и журналы, если достаточно найденных строк и фрагмента ошибки.
- Не перечитывай неизменённые инструкции и исходники. Перечитывание оправдано
  изменением файлов, утратой нужного контекста или конкретной неопределённостью.
- Объединяй независимые поиски и чтения. Не запускай повторно прошедшие проверки
  без изменений кода, нового сбоя или непроверенного сценария.
- Не создавай тесты, планы и отчёты ради формальности. Для исправления поведения
  выбирай проверку результата, а не тест, повторяющий устройство реализации.
- Не копируй инструкции, архитектуру и историю работы в ответы. Обновляй документацию
  при изменении устройства системы; не дописывай в неё хронику каждой доработки.
- Новую сборку запускай после последних правок; не пересобирай тот же код повторно.
  Экономия не отменяет необходимые проверки и не оправдывает пропуск ошибок.
